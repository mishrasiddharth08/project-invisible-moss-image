# Bounded live MOSS speed verification — 2026-10-20

The installed extension completed real native Gradio Generate requests on a
single RTX 5090 32 GB, using the MOSS SFT INT8 ConvRot checkpoint, matching
Qwen3.5-9B INT8 ConvRot encoder and FLUX.2 VAE. Images were 1024×1024 with
seed 20261017 and the same red-mug/green-apple photograph prompt. This verifies
the native UI backend and saved output; it is not a browser-click claim or
certification of all integration acceptance areas.

Runtime: Python 3.13.15, Torch 2.13.0+cu130, Comfy-Kitchen 0.2.39,
Transformers 4.57.6, safetensors 0.8.0, Gradio 4.40.0, Pillow 13.0.0;
Forge Neo 2.30.1 on Windows 11. Forge reported FlashAttention and native
TensorWise INT8 layouts. Different GPUs, kernels and software can behave differently.

Times include native request overhead, conditioning, sampling, decoding and
saving. Cold runs include model transfers and caches. The recovery run followed
a restart, so it is not a warm speed comparison. CPU-cached Manual was slower
than the 29.13s warm full baseline. Adaptive CPU caching took
25.58s; GPU caching took
21.82s, about
1.33× the baseline throughput
in this one scene. No upstream 2–2.5× speed claim is adopted.

Manual recorded 48 real / 52 forecast branch calls; Adaptive recorded 40 real /
60 forecast. Histories peaked at 384.32 MiB with the 512 MiB cap. GPU caching
cost additional VRAM. Device and system RAM were sampled every 0.5 seconds;
these are not exact allocator high-water measurements. Forge private commit
and resident RAM were also sampled. Short repeated runs showed varying cache
and memory use; they do not establish long-term leak-free operation.

Both served MOSS panels had 11 inline controls and no accordion ancestors.
Cold/warm baseline pixels matched exactly. DMD repeated exactly, forced eight
actual Euler/MOSS evaluations, CFG 1 and Spectrum Off, and recorded the pinned
LoRA hash at strength 0.7. It changed pixels relative to the unadapted 8-step
CFG-1 control. Disabling the adapter restored that control pixel-for-pixel.

Visual inspection found coherent mug/apple/table outputs. Spectrum made small
detail and texture changes. DMD looked sharper than the poor unadapted 8-step
control in this scene, while changing composition and adding steam. This is
not a general quality score; hands, typography and diverse scenes remain untested.

## Failure and recovery

Live testing exposed Forge swallowing a Script.process validation exception
and continuing ordinary generation. Invalid MOSS settings now arm a request-owned
core init guard, before LoRA activation, conditioning and sampling. The repeated
invalid DMD/additional-LoRA request returned the intended clear error and no image.
The first failed acceptance output and diagnostic evidence were retained privately.

The native interrupt stopped only our identified active request at 10/50 steps
(18 real / 2 forecast calls). The server returned to idle. A post-fix Adaptive
recovery reproduced its original complete pixels exactly. Final DMD generation
and unpatch recovery also matched their respective references. User config.json
remained byte-identical across the complete sequence.

64 CPU regressions passed; the installed-backend adapter class was skipped in
that CPU suite because it initializes CUDA. Numerical CPU CI and no-Torch checks
remain separate overlapping subsets. Full BF16 inference, physical smaller-card
tests, arbitrary adapter combinations, OOM-budget sweeps and full blueprint
certification are outside this bounded result. No weights or private output images
are included in the public repository.
